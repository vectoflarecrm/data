# Roadmap

Phase-by-phase implementation plan for **Global Watersports B2B Intelligence DB**.

Quality gate after every phase: `pytest && ruff check .`. Integration phases also require `docker-compose up -d postgres && alembic upgrade head`.

## Phase 0 — Analysis (this phase)
- Architecture, database, roadmap docs written.
- ERD designed; indexes/unique constraints/normalization reviewed. STOP here per spec before coding.

## Phase 1 — Project bootstrap
- pyproject.toml, src layout, config (pydantic-settings), logging, FastAPI app, async PostgreSQL session, `/health`, pytest + ruff setup, `.env.example`, `docker-compose.yml` (PostgreSQL 16), Makefile, basic README.

## Phase 2 — Database
- SQLAlchemy models for all core tables with native PG enums, UUID PKs, FKs, indexes, constraints.
- Alembic environment + autogenerated initial migration.
- Integration tests against real PostgreSQL (session scoped test DB).

## Phase 3 — Repository + API
- Repositories per entity, Pydantic schemas (CRUD DTOs), pagination/filtering/sorting.
- API: companies, contacts, products, brands, evidence, events, scores, stats.
- Unit + integration tests.

## Phase 4 — CSV import/export
- Column detection, normalization (name/url/email/phone/domain), dedupe, conflict detection, import evidence (IMPORTED_DATA), import quality report, CSV export.
- Test: import -> normalize -> dedupe -> persist -> export -> re-import (no duplicates).

## Phase 5 — Research queue
- research_tasks repository, FOR UPDATE SKIP LOCKED claiming, worker loop, retries (exponential backoff), scheduling next research, idempotent task creation, multi-worker safety, sweeper for stale RUNNING.
- Multi-worker tests verifying single processing.

## Phase 6 — Crawler
- CrawlerProvider protocol, CrawlResult schema, Crawl4AIProvider, HttpxProvider, PlaywrightProvider (optional), page prioritization, depth/page/delay/timeout/retry limits, content hash. Mock network in tests.

## Phase 7 — Gemini CLI adapter
- AIProvider protocol, GeminiCLIProvider (subprocess, timeout, stdout/stderr, JSON extraction), Pydantic AI result schemas, MockAIProvider. Tests: valid/invalid/partial JSON, timeout, CLI missing, CLI error.

## Phase 8 — Research engine
- Company/product/brand/contact/email/phone/public business WhatsApp/social discovery, verification, buying-signal detection. Integration tests with mocked providers.

## Phase 9 — Evidence + conflict resolution
- Evidence persistence, confidence, source priority ranking, duplicate evidence detection, conflicting claims, conflict tasks. Test no silent overwrite of high-confidence data.

## Phase 10 — Lead scoring
- Deterministic lead score, data completeness, research priority function, configurable weights. Test cases: excellent lead, poor lead, high potential but incomplete, complete but low potential.

## Phase 11 — AI context
- Company intelligence summary, contact summary, buying-signal summary, outreach preparation object. Regenerable from underlying data.

## Phase 12 — End-to-end
- 20 fictional companies sample CSV -> import -> research queue -> mock crawler -> mock AI -> evidence -> contacts -> social -> score -> export. Definition-of-done checklist verified.

## Definition of Done (V1)
PostgreSQL works, Alembic works, FastAPI starts, health works, CSV import/export work, duplicate detection works, evidence works, research queue works, multi-worker works, retry works, crawl adapters work, Gemini CLI adapter works, AI output validation works, enrichment works (company/email/phone/public WhatsApp/social/product/brand), buying signals work, scoring works, API works, tests pass, ruff passes, no hardcoded credentials, no Redis, no fabricated contact info, documentation exists.
